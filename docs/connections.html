EYEAR 연결 구조

실제 Node, 월드모델, 중앙 에이전트, 가전, 앱이 무엇으로 이어지는지와 지금 각 구간이 준비됐는지를 정리했습니다. MQTT는 모두 반석 노트북의 브로커를 거칩니다. 월드모델에서 중앙으로는 HTTP입니다.

MQTT (브로커를 거침) HTTP 방식 미정 동그라미 숫자는 아래 표의 흐름 번호

흐름별 내용과 준비 상태

#무엇을보내는 쪽 → 받는 쪽방식 · 토픽/경로상태
① 방 상태 (1초마다 + 바뀔 때), Node 켜짐·꺼짐 Node → 월드모델 MQTTeyear/v0/{room_id}/state
eyear/v0/{room_id}/status		 월드모델 쪽 필요
Node는 0.2로 보냄. 월드모델 파서가 "0.1"만 받아서 실제 Node 메시지 421개 중 0개 통과. 버전만 맞추면 449개 모두 통과하고 방1 상태가 Node와 똑같이 따라감 (테스트로 확인). MQTT 구독 코드도 아직 없음. status 토픽은 아직 안 받음.
② 집 전체 상태 (WorldSnapshot 2.0) 월드모델 → 중앙 HTTPPOST /v2/world/sessions
POST /v2/world/snapshots		 월드모델 쪽 필요
중앙은 받는 경로가 있음. 월드모델에 보내는 코드가 아직 없음.
③ 말할 문장 ("A님, 주무실 건가요?", "네, 불을 켤게요") 중앙 → Node MQTTeyear/v0/{room_id}/speak 준비됨
중앙이 보내는 형식(0.1)을 Node가 받음. 실제로 이어서 돌려 본 적은 없음.
④ 질문에 대한 대답, "하이 엘지" 뒤 명령 (텍스트만) Node → 중앙 MQTTeyear/v0/{room_id}/voice/reply
eyear/v0/{room_id}/voice/command		 준비됨
중앙이 0.x 버전을 모두 받고 모르는 필드는 무시. 실제로 이어서 돌려 본 적은 없음.
⑤ 가전 명령 중앙 → 가전 MQTTeyear/v0/device/{device_id}/command 확인 필요
중앙은 보내는 코드가 있음. 시뮬레이터는 지금 브라우저 안 버스로 같은 토픽 규칙을 씀. 실제 브로커에 붙는지 확인 필요.
⑥ 가전 상태·실행 결과 가전 → 월드모델 MQTTeyear/v0/device/{device_id}/state
eyear/v0/device/{device_id}/result		 확인 필요
시뮬레이터 README 기준 토픽.
⑦ 가전 실행 결과 전달 월드모델 → 중앙 HTTPPOST /v2/world/device-results 월드모델 쪽 필요
②와 같이 보내는 코드 필요.
⑧ 사람별 선호 (예: A 24°C, B 26°C) 앱 → 월드모델 미정 정해야 함
코드에서 연결 방식을 찾지 못함. 시연의 A = MEMBER_D(이효창)로 프로필을 맞춰야 함.
⑨ 운영자 제어 (일시정지·재개·초기화) 앱 → 중앙 HTTPPOST /v1/control 확인 필요
중앙은 받는 경로가 있음. 앱 쪽 연결은 확인 못함.

처음 연결 테스트 전에 할 일

신반석 (Node · 브로커)

  • 브로커를 같은 와이파이에서 접속할 수 있게 열고 아이디·비밀번호 설정 (지금은 반석 노트북 안에서만 접속 가능)
  • 브로커 주소와 접속 정보를 팀에 공유
  • 시연 공간에서 Node 위치 고정 (옮기면 레이더 위치를 다시 재야 함)

이효창 (월드모델)

  • node_input.py: schema_version "0.1", "0.2" 둘 다 받기 (한 줄)
  • 브로커에서 eyear/v0/+/state 구독 → NodeHub에 넣기
  • 중앙으로 HTTP 보내기 (②, ⑦)
  • identities·프로필: 시연의 A = MEMBER_D

송정빈 (중앙)

  • 중앙 서버를 브로커 주소로 실행 (MQTT 구독·발행 코드는 이미 있음)
  • 월드모델이 접속할 HTTP 주소 공유 (기본 포트 8765)

정예원 (앱)

  • 선호 설정을 월드모델에 넘기는 방식 정하기 (⑧)
  • 운영자 제어를 POST /v1/control로 보내는지 확인 (⑨)
